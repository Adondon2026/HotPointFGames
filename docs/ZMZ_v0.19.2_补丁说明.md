# ZMZ v0.19.2 拆家大战补丁说明

> 修复版本：**v0.19.2**  
> 修复对象：`Zmz_dev` 分支的 `v0.19.1`  
> 仅修复两个前端行为；不改拆家战斗规则、增益种类、音频编曲或其他小游戏，也不修改 `main`。

## 1. 增益勾选数量实时变化

**复现情况：** 设置窗口展开「允许出现的增益」，逐个勾选或取消时，「已选 X / 16」仍显示刚打开设置时的旧数字，要等退出并重新进入设置才更新。

**根因：** `siegeBuffChoiceUI()` 只在创建复选框时使用服务器设置计算并写一次「已选」文本；后续 `onchange` 仅调用 `saveSiegeSettings()`，没有重新统计当前勾选项。

**补丁：** 新增 `updateSiegeBuffCount()`，直接统计当前 UI 中的选中项，并在每个复选框变化及「全选」「全不选」操作时先更新数量、再调用原有服务端保存流程。原有房主权限和后端增益白名单不变。

## 2. 再次进入战场自动恢复背景音乐

**复现情况：** 上一次选择「海浪琶音」或「轻快像素」，退出后再次进入对局，曲目选择被记住，但没有音乐，需要反复点音乐切换按钮才有声音。

**根因：** 原设计只在新建/加入房间的 `enter()` 主动启动音频；游戏厅自动恢复现有房间使用 `enter('state')`，上一补丁为避免未初始化的音频模块异常而跳过了该启动。对局恢复时，音乐状态没有与房间进入事件同步。此外 Android WebView 默认可能要求用户手势才能播放。

**补丁：**
- 在同步开炮、实时开炮和回合制三种战场的首次进入逻辑中，调用 `siegeAudio.enterBattle()`，恢复 `localStorage.siege_bgm` 已保存的曲目，**不自动切换曲目**；用户上次选择「关闭」则继续静音。
- 用户离开战场时停止音乐，重新进入时重新播放；页面重新可见时可以尝试恢复音频。
- Android WebView 设置 `mediaPlaybackRequiresUserGesture=false`，允许应用内自动恢复已选背景音乐。普通浏览器仍可能按自动播放策略限制无手势播放，此时**首次点击战场即可恢复**，不必反复切换音乐曲目。
- 顺便避免点击音乐切换按钮时重复启动并立即重启同一段音频。开炮音效开关仍独立生效。

## 3. Android / 更新与合并兼容

- 保留 `-PzmzBuild=true` 的条件构建方式：师兄的正常构建包名不变，ZMZ 开发版独立安装。
- 补丁 APK：`HotPointFGames-ZMZ-v0.19.2-debug.apk`；版本代码 `8`、版本名 `0.19.2-ZMZ`。
- ZMZ 游戏更新通道：`zmz-game-v0.19.2-...`；仍不会读取主线 `game-...`。
- 除 Android `GameActivity.kt` 的 WebView 音频许可设置及条件版本号外，其余变更只涉及拆家前端、小范围测试/文档/CI。
- 因修改了 Android 宿主 WebView 设置，要完整体验自动播放修复，**需要安装本次新 APK**。只导入新的 Python 游戏文件也可以修复增益计数和房间进入时的音频恢复尝试，但不能改变旧 APK 的 WebView 播放策略。

## 4. 验证项目

新增 `game_source/tests/test_siege_state_controls.js`：
- 使用真实增益控制器逻辑模拟逐项勾选与「全选」「全不选」，断言「已选 2 / 16」→「已选 1 / 16」→「已选 16 / 16」→「已选 0 / 16」立即变化。
- 使用模拟 `AudioContext` 与保存的「轻快像素」曲目，断言首次进入战场自动启动、退出停止、再次进入能重新启动且不改变所选曲目。
- 检查三种战斗模式均有进入战场恢复逻辑，以及 Android WebView 已开启相应设置。

GitHub Actions 会同时运行原来的游戏单元测试、页面回归测试和 Android 编译。手机端仍应实测：恢复上一首音乐、增益选择实时计数、音乐关闭状态保持、开炮音效独立工作。

**上游主分支 `main` 未修改。**
